# 90X web

The Next.js 16 app (React 19, Tailwind v4, Drizzle on Supabase). Setup is in the
root [README](../README.md#running-your-own-copy) and the rules are in
[CONTRIBUTING](../CONTRIBUTING.md). This page lists what is in this folder.

## Commands

Run from `web/` with Bun.

| Command                               | What it does                                                                          |
| ------------------------------------- | ------------------------------------------------------------------------------------- |
| `bun run dev` / `build` / `start`     | Next dev server, production build, serve the build                                    |
| `bun run db:start` / `db:stop`        | Start or stop the local Supabase (Docker)                                             |
| `bun run db:reset`                    | Rebuild the local database from every migration                                       |
| `bun run db:new <name>`               | New SQL migration in `../supabase/migrations/`                                        |
| `bun run db:pull`                     | Regenerate `src/db/pulled/` from the local database                                   |
| `bun run db:push` / `db:types`        | Push migrations to, or generate Supabase types from, the database in `DIRECT_URL`     |
| `bun run admin:grant <email>`         | Make a signed-in user an admin                                                        |
| `bun run schedule:jobs`               | Create the QStash schedules (needs a public `NEXT_PUBLIC_APP_URL`)                    |
| `bun run typecheck` / `lint` / `test` | TypeScript, ESLint plus oxlint, Vitest                                                |
| `bun run format` / `format:check`     | oxfmt                                                                                 |
| `bun run test:e2e`                    | Playwright against a running seeded build                                             |
| `bun run check:*`                     | The checks CI runs, listed in [CONTRIBUTING](../CONTRIBUTING.md#before-you-open-a-pr) |
| `bun run break-in`                    | Security attack suite against the local stack                                         |

Scripts that read `.env.local` (`db:push`, `db:pull`, `db:types`, `admin:grant`,
`schedule:jobs`, `backfill:xp`, `fix:card-missions` and the model checks) hit
whatever database that file points at. Fill it with local values unless you mean
production.

## Layout

```
src/app/(app)/   signed-in pages: today, feed, library, coach, friends, me
src/app/admin/   admin pages
src/app/api/     health, coach chat, push resync, QStash jobs, test sign-in
src/app/actions/ server actions
src/lib/         logic per area, pure rules next to their tests
src/components/  UI
src/db/          Drizzle schema (pulled/ is generated)
src/proxy.ts     the Next 16 middleware: session refresh and traffic source
public/sw.js     the service worker (push and offline Today and Feed)
e2e/             Playwright specs, seed and the fake model
scripts/         checks, icon and archetype generation, load/ and break-in/
```
